# raylib-ltop-engine

An engine built on [raylib](https://www.raylib.com/) that mimics the functionality of The Legend of Zelda: A Link to the Past. `NOTES.md` is the design spec; this file covers how the code is actually put together.

## Quick start

```bash
./build-mac.sh     # generate assets, build native binary "main", sync "assets/"
./main             # run (assets/ must sit next to the binary)
```

Web build (requires [emscripten](https://emscripten.org), e.g. `brew install emscripten`):

```bash
./build-web.sh     # output: build/web/ (index.html + wasm + packaged assets)
cd build/web && python3 -m http.server   # browsers refuse file:// for wasm
```

Resource editor (Tauri desktop app):

```bash
cd editor
npm install
npm run tauri:dev    # or: npm run tauri:build to bundle a .app/.dmg
```

The generator requires the project's `.venv/bin/python3` (stdlib only, no pip packages).

## Core rule: the binary never parses data files

`scripts/generate_assets.py` reads every `.json` (dialogues, characters, rooms — including each room's tile layers) and the tileset `.png` dimensions, and emits `include_auto/assets.h` + `src_auto/assets.cpp` with the same information as C arrays/structs. Runtime file loading happens **only** from `assets/`:

- Tileset image, character sprite sheets, music, sfx, font, UI bitmaps are copied from `resources/` to `assets/` by the generator (excluding `.json`/`.DS_Store`).
- The generator also creates `resources/ui/border.png` (LttP-style 24x24 nine-patch dialogue border, 8px patches) if it is missing — the only resource file the tooling invents.
- Optional json fields must stay optional: missing `spawn`, `music`, `walk_sfx`, `dialogue`, `repeat`, etc. are handled with defaults/`-1`/null both in the generator and the engine. If you add a field, follow that pattern.

## Rooms (no Tiled)

Rooms are pure `.json` in `resources/rooms/`. The web editor is the only map-editing tool: it paints the `decor`/`colliders` layers, places the spawn and encounter markers, resizes rooms, and picks hero/music/walk-sfx. The file shape:

- `width`, `height` — map size in 32px tiles.
- `decor`, `colliders` — flat arrays of `width*height` tile ids; ids are 0-based frame indices into the tileset **+ 1** (0 = empty). Colliders block movement but are still drawn (drawn above decor).
- `default`, `encounters` — see NOTES.md.

The tileset is a single `.png` of 32x32 tiles in `resources/tiles/` (first `.png` alphabetically); its columns/tile-count are derived from the image dimensions, so no `.tsx` metadata exists. Legacy Tiled `.tmx`/`.tsx` files are ignored — the editor offers to delete a room's leftover `.tmx`.

## Architecture

- `include/engine.h` — constants (`TILE_SIZE` 32, `VIRTUAL_HEIGHT` 224, `ACTION_KEY`), `Direction` enum (down/right/left/up order matches the json), data structs consumed from generated code (`CharacterConfig`, `Dialogue`, `Encounter`, `RoomConfig`, `TilesetConfig`), `actionPressed()`, `virtualScale()`.
- `src/main.cpp` — boot, room loading, music streaming (never restarts an already-playing file), the encounter system, the camera (centered on the hero, clamped to map bounds), and the platform split:
  - `updateAndDraw()` is the frame body; on web (`-DPLATFORM_WEB`) it is registered via `emscripten_set_main_loop`, on desktop it runs in the `while (!WindowShouldClose())` loop. Keep new per-frame logic inside `updateAndDraw`.
  - One-shot encounter memory: `encounterFired` is a global `bool[]` sized by generated `ENCOUNTER_TOTAL`, never cleared on room load. Encounters carry a globally-unique baked `id`; `repeat: true` bypasses the check.
- `src/room.cpp` — draws `decor` then `colliders` layers (both render; colliders also block), tile collision (`solidBox`, out-of-bounds counts as solid), per-room walk sfx.
- `src/hero.cpp` — movement + input (arrows/dpad/stick, diagonal normalized by 0.7071, axis-separated collision so the hero slides along walls), position clamped to map bounds, facing, stand/move animation from baked frame lists, step sfx every 32px of Euclidean movement.
- `src/dialogue.cpp` — nine-patch border via `DrawTextureNPatch`, typewriter (~30 cps) with word wrap (recomputed per line, measured in virtual pixels), `message.wav` per non-space letter, `message_finish.wav` when a line completes, action button skips/advances/closes.
- Rendering: a `Camera2D` with `zoom = screenHeight/224` gives the virtual resolution; UI is drawn after `EndMode2D` scaled by `virtualScale()`. Textures use `TEXTURE_FILTER_POINT`.

Coordinates: json `location`/`spawn` values are tile units (multiplied by 32 internally); everything inside the engine is pixels.

## Generated data shapes

`RoomConfig.rooms[].hero` is an index into `CHARACTERS`, and encounter `dialogue` is an index into `DIALOGUES` (or `-1`). Tile ids in the baked `decor`/`colliders` arrays are already 0-based frame indices **+ 1** (0 = empty). `TILESET` is a single global tileset from the first `.png` in `resources/tiles`.

## Conventions and gotchas

- Build with `clang++` (not `clang`) — the C++ code uses `new`/`delete`; `clang` won't link libc++.
- Keep code C++11-flavored and free of desktop-only headers so console ports (PSP/Dreamcast) and emscripten stay viable; web-only APIs must sit behind `#if defined(PLATFORM_WEB)`.
- The vendored `include/raylib.h` is raylib 6.x; native builds link via `pkg-config raylib`. The web script downloads raylib source (tag override with `RAYLIB_TAG`, existing checkout with `RAYLIB_SRC`) and builds `libraylib.web.a` with emmake. Header/lib version skew is tolerated because only long-stable raylib APIs are used.
- `.venv/`, `assets/`, `build/`, `include_auto/`, `src_auto/`, the `main` binary, `editor/node_modules/`, `editor/dist/`, and `editor/src-tauri/target/` are gitignored.
- The editor's Rust backend only serves `resources/` read-only for previews and refuses any write outside `resources/` (`.json` via save/create, binary uploads restricted per-directory). Its Build button shells out to `./build-mac.sh` and is rejected on non-darwin platforms. It locates the repo via `LTOP_EDITOR_PROJECT`, a persisted folder choice, or by walking up from the executable; otherwise it asks for the folder in the UI.
- Smoke test any change: build, run `./main` for a few seconds (raylib logs every file it loads — they should all be `assets/...`), and exercise arrow-key movement, the instant encounter at tile (5,5), and the interactive one at (6,6) with Z.
- Music is loaded synchronously inside raylib's tracker parser (jar_mod/jar_x). A corrupt or malformed module file can hang `LoadMusicStream` forever, **before the first frame — the window never opens and nothing is logged**. This happened with a bad `zelda 4 - maintheme.mod` (4KB of garbage that `ffmpeg` also rejects). If the game starts but no window appears, suspect the room's `music` file first: swap it for a known-good one and re-run.
